# OmniGuard V2X v3.0.3 Release Checklist

Expected tag: `v3.0.3`

## Automated gates before merge

- [ ] Canonical VERSION / CMake / Go release identity is exactly 3.0.3.
- [ ] Python security regression suites pass.
- [ ] Current tracked-tree secret scan passes without printing secret values.
- [ ] Commit-bound release integrity manifest generates and verifies.
- [ ] Deterministic SBOM generates.
- [ ] Build provenance binds exact HEAD/tree/toolchain metadata.
- [ ] Adversarial validation passes.
- [ ] Software-HIL validation passes.
- [ ] Incident-response validation passes.
- [ ] Hardened native configure fails closed without real liboqs.
- [ ] Pinned liboqs real-PQC build passes.
- [ ] v3.0.3 native persisted-runtime self-test passes.
- [ ] Durable PQC keystore self-test passes.
- [ ] Guarded key-rotation self-test passes.
- [ ] Signed trust-keyring self-test passes.
- [ ] Mixed-generation native ledger validation passes.
- [ ] Unadmitted historical key is rejected.
- [ ] Admitted historical ML-DSA ledger is accepted.
- [ ] Historical ML-KEM re-decapsulation remains explicitly false.
- [ ] Rollback anchor initialize/advance and copied-old-state rejection pass.
- [ ] Recovery candidate check never auto-restores a historical key.
- [ ] Hardware-required software provider is rejected.
- [ ] Explicit tpm2/pkcs11/hsm requests fail closed until implemented.
- [ ] Go security tests and bounded fuzz campaigns pass.
- [ ] Publication package SHA-256 verification passes.

Any source change after a successful run requires the full final gate to run again because integrity/provenance evidence is commit-bound.

## Manual repository/security operations

These are repository/deployment controls and are not safely auto-applied by source code:

- [ ] Enable/confirm `main` branch protection and require the final Security Baseline check.
- [ ] Enable/confirm GitHub private vulnerability reporting and secret scanning where account/repository features permit.
- [ ] Rotate any credentials that were ever committed historically.
- [ ] Decide whether a coordinated Git-history rewrite is approved; do not rewrite shared history opportunistically.
- [ ] Confirm collaborators/CI/deployments use newly rotated credentials after any remediation.

## After merge

- [ ] Verify the merged `main` tree contains no unexpected changes.
- [ ] Verify Security Baseline passes on the exact final `main` merge commit.
- [ ] Run `bash scripts/create_v3_0_3_tag.sh --check-only` locally if using the CLI operator path.
- [ ] Create `v3.0.3` only from the exact validated current `main` commit.
- [ ] Use `docs/releases/v3.0.3.md` as the release body.
- [ ] Publish only artifacts regenerated from the tagged commit.
- [ ] Verify `SHA256SUMS` before upload/publication.
- [ ] Never attach environment files, private keys, wrapping credentials, raw sensitive logs, or unreviewed build directories.

## Claim boundary

- [ ] Release wording does not claim production certification, vehicle-safety certification, formal verification, hack-proof security, real HSM custody, or hardware monotonic rollback protection.
