# OmniGuard V2X v3.0.3 Release Checklist

Expected tag: `v3.0.3`

This checklist defines the release gates. Automated items are intentionally left unchecked in source until the exact final `main` commit is validated; the guarded tag workflow independently refuses publication unless the required exact-commit workflows complete successfully.

## Automated gates before tag

- [ ] Canonical VERSION / CMake / Go release identity is exactly 3.0.3.
- [ ] Python security regression suites pass.
- [ ] Secure local credential-bootstrap regressions pass.
- [ ] Go backend readiness/runtime-selection regressions pass, including stale-loopback and stale-prebuilt cases.
- [ ] Current tracked-tree secret scan passes without printing secret values.
- [ ] Commit-bound release integrity manifest generates and verifies.
- [ ] Deterministic SBOM generates.
- [ ] Build provenance binds exact HEAD/tree/toolchain metadata.
- [ ] Adversarial validation passes.
- [ ] Software-HIL validation passes.
- [ ] Incident-response validation passes.
- [ ] Hardened native configure fails closed without real liboqs.
- [ ] Pinned liboqs real-PQC build passes.
- [ ] v3.0.3 native persisted-runtime self-test passes.
- [ ] Durable PQC keystore self-test passes.
- [ ] Guarded key-rotation self-test passes.
- [ ] Signed trust-keyring self-test passes.
- [ ] Mixed-generation native ledger validation passes.
- [ ] Unadmitted historical key is rejected.
- [ ] Admitted historical ML-DSA ledger is accepted.
- [ ] Historical ML-KEM re-decapsulation remains explicitly false.
- [ ] Rollback anchor initialize/advance and copied-old-state rejection pass.
- [ ] Recovery candidate check never auto-restores a historical key.
- [ ] Hardware-required software provider is rejected.
- [ ] TPM2 and generic HSM requests fail closed because no concrete v3.0.3 adapters are implemented.
- [ ] A PKCS#11 request fails closed when the opt-in adapter is not compiled or when a real token cannot prove the required v3.2 mechanisms/non-exportability boundary.
- [ ] PKCS#11 Source Conformance passes against the canonical OASIS PKCS#11 v3.2 headers.
- [ ] Go security tests and bounded fuzz campaigns pass.
- [ ] Windows Runtime Smoke passes with a freshly built backend, authenticated health, initialized chain verification, and clean loopback process teardown.

Any source change after a successful run requires the full final gate to run again because integrity/provenance evidence is commit-bound.

## Exact-main tag gate

The `Create OmniGuard V2X v3.0.3 Tag` workflow and the local `scripts/create_v3_0_3_tag.sh` operator path must require all of these push workflows to be `completed/success` for the exact current `main` SHA before creating the annotated tag:

- [ ] `Security Baseline`
- [ ] `PKCS11 Source Conformance`
- [ ] `Windows Runtime Smoke`

Both tag paths must also verify that `v3.0.3`/its GitHub Release do not already exist and that the guarded publication workflow is present.

## Publication gates after tag

The guarded `release-v3.0.3.yml` workflow must run from the exact `v3.0.3` tag that equals current `main` and regenerate release evidence from that tagged commit.

- [ ] Tagged release regression suite passes.
- [ ] Tagged native real-PQC build/self-tests pass.
- [ ] Tagged mixed-generation and rollback/recovery validations pass.
- [ ] Tagged Go tests/fuzz campaigns pass.
- [ ] Commit-bound release integrity manifest, SBOM, provenance, and validation reports are regenerated.
- [ ] Publication package `SHA256SUMS` is generated and verified before release upload.
- [ ] Published artifacts come only from the tagged validation package.

## Manual repository/security operations

These are repository/deployment controls and are not safely auto-applied by source code:

- [ ] Enable/confirm `main` branch protection and require the final release checks where repository/account permissions permit.
- [ ] Enable/confirm GitHub private vulnerability reporting and secret scanning where account/repository features permit.
- [ ] Rotate any credentials that were ever committed historically.
- [ ] Decide whether a coordinated Git-history rewrite is approved; do not rewrite shared history opportunistically.
- [ ] Confirm collaborators/CI/deployments use newly rotated credentials after any remediation.

## After merge

- [ ] Verify the merged `main` tree contains no unexpected changes.
- [ ] Verify `Security Baseline`, `PKCS11 Source Conformance`, and `Windows Runtime Smoke` pass on the exact final `main` merge commit.
- [ ] Run `bash scripts/create_v3_0_3_tag.sh --check-only` locally if using the CLI operator path.
- [ ] Create `v3.0.3` only from the exact validated current `main` commit.
- [ ] Use `docs/releases/v3.0.3.md` as the release body.
- [ ] Never attach environment files, private keys, wrapping credentials, raw sensitive logs, or unreviewed build directories.

## Claim boundary

- [ ] Release wording does not claim production certification, vehicle-safety certification, formal verification, hack-proof security, validated production custody on a specific TPM2/HSM/PKCS#11 token, or hardware monotonic rollback protection.
