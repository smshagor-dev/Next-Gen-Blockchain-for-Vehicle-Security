# OmniGuard V2X v4.0.0 Release Checklist

Expected tag: `v4.0.0`

## Canonical Identity

- [ ] `VERSION` is exactly `4.0.0`.
- [ ] CMake project version is exactly `4.0.0`.
- [ ] Go `releaseVersion` is exactly `4.0.0`.
- [ ] Python release metadata reports `4.0.0` and internal hardening phase `v4.0`.
- [ ] Dashboard footer renders the canonical release version dynamically.

## Runtime Security Strength

- [ ] `runtime_security_strength.py` passes regression tests.
- [ ] No synthetic numeric security percentage is generated.
- [ ] Security Strength supports `STRONG`, `GUARDED`, `DEGRADED`, and `RISK`.
- [ ] High/critical explicit alert signals map to `RISK`.
- [ ] Missing/disconnected core runtime evidence fails conservatively to `DEGRADED`.
- [ ] Dashboard Security Strength and vehicle risk indicator share the same source-backed evaluator.

## Python / Runtime Security

- [ ] Full Python security regression suite passes.
- [ ] Credential bootstrap/readiness regressions pass.
- [ ] Current-tree prohibited-secret scan passes.
- [ ] Permissioned consensus, identity, sync, replay/flood, control API, ledger, incident-response, and HIL tests pass.
- [ ] Dashboard navigation, live socket, stable feed, graph, raster asset, and Security Strength tests pass.

## Native PQC / Hardware Boundaries

- [ ] Hardened native target fails closed without real liboqs.
- [ ] Pinned liboqs real-PQC build succeeds.
- [ ] ML-DSA-44 / ML-KEM-512 native self-tests pass.
- [ ] Durable PQC keystore tests pass.
- [ ] Rotation and signed historical trust validation pass.
- [ ] Mixed-generation ledger validation passes.
- [ ] Rollback/recovery-state validation passes.
- [ ] Default unavailable TPM2/HSM/provider requests fail closed.
- [ ] PKCS#11 v3.2 source conformance passes.
- [ ] No production PKCS#11 token custody claim is made without real hardware evidence.

## Go Runtime / Windows

- [ ] Go security tests pass.
- [ ] Bounded Go fuzz campaigns pass.
- [ ] Fresh Windows Go backend build passes.
- [ ] Authenticated `127.0.0.1:8787` control/health smoke passes.
- [ ] Authenticated `127.0.0.1:8788` live-stream challenge/HMAC/status smoke passes.
- [ ] Windows cleanup confirms ports `8787` and `8788` are released.

## Release Evidence

- [ ] Release integrity manifest is generated and verified against the exact commit SHA.
- [ ] `sbom-v4.0.0.cdx.json` is generated.
- [ ] `provenance-v4.0.0.json` is generated.
- [ ] Adversarial validation report is generated.
- [ ] Software-HIL validation report is generated.
- [ ] Incident-response validation report is generated.
- [ ] Publication payload SHA-256 checksums verify successfully.

## Exact-Main Release Gates

The exact final `main` SHA must have successful `push` runs for:

- [ ] `Security Baseline`
- [ ] `PKCS11 Source Conformance`
- [ ] `Windows Runtime Smoke`

Do not create the tag from a PR-only workflow run.

## Tag & Publication

- [ ] Run `scripts/create_v4_0_0_tag.sh --check-only` from clean, synchronized `main` if using the local operator path.
- [ ] Confirm no existing `v4.0.0` tag exists.
- [ ] Confirm no existing `v4.0.0` GitHub Release exists.
- [ ] Create annotated `v4.0.0` only on the exact validated current `main` SHA.
- [ ] Publication workflow verifies the tagged SHA still equals current `main`.
- [ ] Publication workflow re-runs release tests from the tag.
- [ ] GitHub Release body is `docs/releases/v4.0.0.md`.
- [ ] Published binaries/evidence are generated from the tagged commit, not copied from an older release.

## Repository Security Operations

- [ ] Confirm `main` branch protection / required release checks where repository settings permit.
- [ ] Confirm private vulnerability reporting and secret-scanning settings where available.
- [ ] Confirm any historically exposed real credentials have been rotated externally.
- [ ] Decide separately whether a coordinated Git-history rewrite is approved; do not rewrite history during normal release publication.

## Claim Boundary

- [ ] Release remains described as research hardening / validation software.
- [ ] No production automotive certification claim.
- [ ] No ISO 26262/ASIL claim.
- [ ] No formal verification claim.
- [ ] No vulnerability-free claim.
- [ ] No hardware-monotonic rollback claim.
- [ ] No production HSM/TPM/PKCS#11 custody claim without device-specific evidence.
