# Reviewer Issue Resolution Matrix

This matrix records how the project corrected major reviewer-facing claim problems. The current status is `corrected_but_requires_new_experiments`: claims have been narrowed and limitations are documented, but larger-scale validation is still required before resubmission.

| Reviewer issue | Original problem | Resolution | Evidence files | Current limitation | Claim status |
|---|---|---|---|---|---|
| Overstated post-quantum security | Wording implied full post-quantum security while Pedersen/Schnorr-style components rely on classical discrete-log assumptions. | Reframed as hybrid security: PQ key establishment path with classical commitment/proof components. | `docs/security-assumptions.md`, `security_capabilities.py`, `api/go/main.go`, `dashboard.py`, `readme.md` | Full PQ security requires replacing classical commitment/proof components with PQ-safe alternatives. | Full PQ claim removed. |
| Invalid Sybil-resistance theorem | DID identity authenticity was overstated as Sybil resistance under open registration. | Added identity admission-policy metadata and documented that open registration has no Sybil-resistance guarantee. | `docs/identity-security-model.md`, `identity_security.py`, `smartcar_backend.py`, `dashboard.py`, `tests/test_identity_security.py` | Sybil resistance requires external admission control such as authority enrollment, stake, work, or certificates. | Sybil-resistance claim removed for open registration. |
| Incorrect 51% attack theorem | Dual hashing was framed as preventing 51% or majority-control attacks. | Separated retroactive tamper evidence from forward consensus capture; majority attack resistance is false under simple majority. | `docs/consensus-threat-model.md`, `consensus_security.py`, `api/go/main.go`, `dashboard.py`, `tests/test_consensus_security.py` | Production consensus safety requires BFT/stake/certificate controls and bounded trust assumptions. | Majority-attack-resistance claim removed. |
| Weak FL evaluation | Three peers, 10 samples per peer, 24-sample test set, one Byzantine peer, trivial 100x attack, and single trial were too small for robustness claims. | Reframed as prototype FL poisoning sanity check and added future validation scaffold. | `docs/fl-validation-limitations.md`, `experiments/fl_validation_plan.py`, `federated_learning.py`, `dashboard.py`, `tests/test_security_claims.py` | Needs real dataset/model, multi-seed trials, larger peer counts, stronger attacks, and confidence intervals. | Byzantine-robustness claim removed. |
| 100% detection / trivial attack tests | Detection claims were based on single trivial triggers such as 350 km/h speed and 100x FL delta. | Reframed as single-run adversarial sanity checks; disabled detection-rate headlines. | `docs/adversarial-validation-limitations.md`, `security_capabilities.py`, `api/go/main.go`, `dashboard.py`, `tests/test_security_claims.py` | Needs randomized multi-seed trials, realistic noise, stealth attacks, FP/FN, precision/recall/F1, ROC/AUC where applicable. | General 100% detection claim removed. |
| Inconsistent layer counts | Paper/system references varied between 13, 6, and 5 layers. | Standardized to six implemented prototype layers. | `readme.md`, `tests/test_security_claims.py` | Layering is a prototype organization, not a formal security proof. | Canonical layer count fixed. |
| Inconsistent latency numbers | Draft references differed between 5.34 ms and deprecated 3.57 ms. | Added metrics source of truth and retained only 5.34 ms warm-start prototype pipeline latency as active. | `docs/metrics-source-of-truth.md`, `readme.md`, `tests/test_security_claims.py` | Single prototype environment; not a production SLA or cross-platform benchmark. | Canonical latency fixed. |
| Unclear novelty | SES/privacy layer could read as claiming new cryptography while using known primitives. | Added contribution boundary: no new cryptographic primitives; contribution is system integration, architecture, validation instrumentation, and security-boundary reporting. | `docs/contribution-boundary.md`, `security_capabilities.py`, `api/go/main.go`, `dashboard.py`, `readme.md` | Novelty remains engineering integration; new-crypto claims are not made. | New-crypto claim removed. |
| O(n) vs O(n²) complexity mismatch | Broad O(n) complexity claim did not explain full-mesh/gossip/broadcast behavior. | Added component-level complexity analysis and API metadata; full-system O(n) claim is false. | `docs/complexity-analysis.md`, `security_capabilities.py`, `api/go/main.go`, `dashboard.py`, `readme.md` | Naive all-to-all communication can still produce O(n²) network volume; mitigation is future work. | Whole-system O(n) claim removed. |
| Pedersen aggregate-statistics claim | Wording suggested aggregate statistics or mean velocity could be recovered directly from hidden commitments. | Added Pedersen mode model: default COMMIT_ONLY; homomorphic combination supported but aggregate statistics are not recoverable without openings or a separate protocol. | `docs/pedersen-aggregation-model.md`, `zkp_privacy.py`, `api/go/main.go`, `dashboard.py`, `readme.md` | Secure aggregation / ZK disclosure for aggregate statistics is not implemented. | Secure-aggregation/statistics claim removed. |
