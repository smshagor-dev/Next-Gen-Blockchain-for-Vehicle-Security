## Contributing

## How to Contribute
1. Fork or branch from the latest code.
2. Create a focused branch (`feature/*`, `fix/*`, `docs/*`).
3. Keep commits small and scoped.
4. Include tests or reproduction steps with fixes.
5. Submit a pull request with:
- Problem statement
- Proposed change
- Validation steps

## Pull Request Checklist
- Code compiles (`py_compile` for Python files).
- No silent `except: pass` added.
- `.env` keys documented if changed.
- `readme.md` updated for user-facing behavior changes.
- No secrets/private keys committed.

## Reporting Issues
Please include:
- Expected behavior
- Actual behavior
- Error logs/traceback
- OS and Python version
- Reproduction steps

## Style Summary
- Keep code ASCII where possible.
- Add docstrings for new public methods.
- Prefer explicit logging for recoverable failures.
